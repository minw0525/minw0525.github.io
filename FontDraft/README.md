# FontDraft

iPad에서 글자를 그리고, 윤곽선과 노드를 다듬어 공유하는 서체 아이디에이션 웹앱.

현재는 프로젝트·글리프 편집과 UFOZ 저장까지 연결한 시제품이다. 펜·사각형·타원·면 브러시·지우개·나이프와 수치 변형을 지원한다. 확정한 편집은 기기에 자동 저장하며, UFOZ를 내려받아 새 세션에서 다시 열 수 있다. 위치 주석과 면 합치기·빼기도 지원한다. 문자열 SVG·PNG 내보내기를 지원한다.

- [구현 명세](./SPEC.md): 확정된 동작, 초기 구현 가정, 검증 기준
- [구현 로드맵](./TODO.md): 단계별 작업과 완료 조건

## 기본 방향

- 프로젝트에서 글리프를 추가하고 해당 글리프 편집창에서 작업한다.
- Shift는 짧게 탭해 고정하고 다시 탭해 해제할 수 있다. 고정 후 손을 떼고 Pencil로 다중 선택·나이프 면 분할을 한다. 누른 채 사용하는 방식도 지원하지만 iPad Safari의 손가락+Pencil 동시 입력은 실기기에서 제한될 수 있다.
- 노드 편집이 기본이며 더블탭으로 해당 컨투어만 전체 선택한다.
- 면 브러시, 지우개, 펜, 기초도형, 나이프와 선택 영역 변형을 제공한다.
- 프로젝트는 표준 UFO 3의 ZIP 형식인 `.ufoz`로 저장한다.
- 첫 버전에서 설치 가능한 폰트 생성은 하지 않는다.

## 기준 기기

사용자가 제공한 검증 환경: iPad Pro 11-inch (4th generation), Wi-Fi / iPadOS 26.6.1 / Apple Pencil 2세대.

데스크톱 브라우저 검증과 실제 iPad 검증은 구분해서 기록한다. 펜슬 필기감, 팜 리젝션, 보조 손 동시 입력은 실기기 검증이 필요하다.

## 실행

```sh
npm install
npm run dev
```

터미널의 Local 주소에서 실행한다. 같은 신뢰할 수 있는 네트워크의 iPad에서는 터미널에 표시된 사설 Network 주소를 사용한다. 개발 서버는 모든 네트워크 인터페이스에서 수신하므로 공개 배포용으로 사용하지 않는다. 외부 네트워크의 주소나 포트 포워딩은 필요하지 않다.

```sh
npm run build
npm test
```

테스트는 설치된 Google Chrome을 사용한다. Node.js 22.14.0에서 빌드·테스트를 확인했다. 의존성의 실제 버전은 package-lock.json에 고정되어 있다.

## 현재 조작

- 노드/핸들 드래그: 이동. 모든 베지어 핸들을 표시하며 핸들만 따로 선택할 수 있다. 겹친 위치에서는 선택 표시를 마지막에 그린다.
- 노드 더블탭: smooth 전환. 세그먼트 주변 더블탭: 해당 컨투어 전체 선택. 구멍 컨투어는 함께 선택하지 않는다. 세그먼트도 다중 선택하며 파란색으로 표시한다.
- 오른쪽 하단 고정 영역의 Shift 버튼을 누른 채 탭: 선택 추가·해제. 데스크톱 Shift도 같은 역할이다.
- 빈 곳 드래그: 영역 선택. 빈 곳 탭: 선택 해제.
- 두 손가락: 패닝·확대. 화면 이동 도구로 한 포인터 패닝도 가능하다.
- 휠 또는 두 손가락 핀치: 확대·축소. 줌 버튼·배율 표시·도움말 버튼은 제공하지 않는다.
- 방향키 또는 미세 이동 버튼: 1 unit 이동. Shift+방향키: 10 units.
- Undo/Redo 버튼 또는 Cmd/Ctrl+Z, Shift+Cmd/Ctrl+Z.
- Escape: 진행 중 동작 취소 및 선택 해제.
- 펜: 탭으로 노드 추가, 드래그로 대칭 핸들 생성. 시작점을 탭해 닫기. ‘열린 경로 완료’ 또는 Enter로 열린 채 확정한다. 도구 변경 시 2개 이상의 점이 있는 초안은 열린 경로로 확정하고, Escape로 초안을 버린다.
- 사각형·타원: 대각선 드래그로 생성한다. ⇧를 누르고 시작하면 정사각형·원이 된다. 드래그 중에는 채움 없이 윤곽선만 표시한다.
- 브러시: 우측 패널에서 크기·납작함·각도를 설정한다. 커서에 실제 단면을 표시한다. 단순화는 기본 3 units, 0–12 범위로 조절한다. 한 획의 설정은 고정되며 펜을 떼면 독립된 면으로 확정한다.
- 지우개: 선택이 있으면 선택한 노드가 속한 닫힌 컨투어들만 차감한다. 선택이 없으면 전체 보이는 면에 적용한다. 열린 경로와 무관한 컨투어는 보존한다.
- 브러시와 지우개는 펜촉 설정을 각각 기억한다. 새 윤곽선을 만들면 그 노드들이 선택된다. 전체 면을 지우려면 선택 도구의 빈 곳 탭이나 Escape로 선택을 해제한다.
- 나이프: 일반 드래그로 교차점에 노드 추가. ⇧를 누른 채 시작한 드래그는 면 분할이며 드래그 중 ⇧를 놓아도 유지된다. 노드 탭은 경로 끊기다. 선택이 있으면 해당 컨투어들만 드래그 대상이다.
- 나이프는 직선 선분의 범위에서만 자른다. 완전히 관통하지 않은 구간은 면 분할하지 않으며, 구멍과 외부를 연결하는 절단은 한 개의 닫힌 컨투어로 연결될 수 있다. 절단은 폭이 없는 경계를 만들며 지우개처럼 면을 제거하지 않는다.
- 선택 도구의 오른쪽 변형 패널: 회전, 가로·세로 크기 조정, 수평 기울이기. 선택 노드 경계 상자의 9개 기준점을 기준으로 노드와 핸들을 함께 변형한다. 비율 잠금을 끄면 가로·세로를 다르게 조정할 수 있다. 패널 아래쪽은 스크롤해서 접근한다.

- 주석: 도구의 ✎를 선택하고 캔버스를 탭해 텍스트를 작성한다. 탭한 좌표에 텍스트박스가 계속 표시된다. 박스에서 내용을 수정하거나 ×로 삭제한다. 포커스를 벗어날 때 확정하며 XY 입력 모달은 없다. 주석은 채움과 면 연산에 참여하지 않는다.
- 면 합치기: 노드를 선택한 닫힌 컨투어들끼리 non-zero 면의 겹침을 정리한다. 안쪽 구멍과 선택 밖 컨투어를 자동으로 합치지 않는다. 떨어진 컨투어는 그대로 유지한다.
- 면 빼기: 선택한 노드가 속한 닫힌 컨투어들을 칼날로 사용해 나머지 닫힌 컨투어에서 뺀다. 실제 차감이 발생하면 선택 칼날은 소비된다. 전혀 겹치지 않으면 변경하지 않는다. 열린 경로와 차감에 영향 없는 컨투어는 유지한다. 합치기·빼기는 선택 도구의 오른쪽 패널에 있으며 각각 Undo 한 단계다.

그리기 중 미리보기에는 면 연산을 수행하지 않는다. 지우개 미리보기의 붉은 영역은 차감할 영역이며 실제 차감은 손을 뗄 때 확정한다. 펜 경로 하나, 도형 하나, 브러시·지우개 한 획은 각각 Undo 한 단계다.

펜슬 입력 중 캔버스의 새 터치 입력은 무시한다. modifier 터치는 별도 처리한다. 두 손가락 제스처가 시작되면 진행 중인 손가락 노드 이동은 취소한다.

## 프로젝트·파일

- 상단 프로젝트 이름을 누르면 기기에 저장된 프로젝트 전환, 새 프로젝트, UFOZ 열기, 프로젝트 이름·스타일·UPM·기준선 편집을 할 수 있다. UPM을 변경해도 윤곽선을 자동 확대하지 않는다.
- 왼쪽 +에서 여러 문자를 입력해 글리프를 한 번에 추가한다. Unicode와 이름은 자동으로 만들고 폭은 공통값을 적용한다. 이미 있는 문자는 중복 생성하지 않는다. 작은 화면에서는 캔버스 상단의 글리프 선택과 +를 사용한다. 오른쪽 글리프 패널에서 이름·문자 코드·폭을 바꾸면 입력 확정 시 자동 적용한다. LSB·RSB도 함께 표시한다. 문자 코드는 공백으로 나눈 16진수이며 매핑 없이 작성할 수도 있다.
- 편집 확정마다 IndexedDB에 자동 저장한다. 새로고침하면 마지막 프로젝트와 글리프를 복원한다. Undo/Redo는 글리프별 최근 100단계를 현재 세션에서만 유지한다. 윤곽선과 주석은 같은 순서의 Undo 이력을 공유한다. 이름·매핑·기준선 변경은 이 이력에 포함하지 않는다.
- 상단 ‘기기에 저장됨’은 브라우저 저장소 상태다. UFOZ 파일 저장은 별도 버튼을 누른다. 다운로드 요청 뒤 실제 파일은 다운로드 목록이나 파일 앱에서 확인한다. 브라우저 데이터 삭제 또는 다른 주소·브라우저에서는 자동저장에 접근할 수 없으므로 파일도 보관한다.
- 프로젝트 전환·파일 저장 시 2개 이상 노드를 가진 펜 초안은 열린 경로로 확정한다. 진행 중 포인터 동작은 취소한다. 새 프로젝트와 가져온 파일은 기존 프로젝트를 대체하지 않고 별도로 추가한다.

### UFOZ 지원 범위

표준 UFO 3.0 / GLIF 2.0, 기본 전경·public.background Mask 및 앱의 추가 마스터 레이어, 직선·3차 베지어, 열린/닫힌 경로, 컨투어·노드 식별자와 smooth 속성, 글리프 순서·이름·복수 Unicode·폭을 저장한다. 공통 정보는 familyName, styleName, unitsPerEm, ascender, descender, xHeight, capHeight다. 기존 단일 전경은 lib의 `org.fontdraft.formatVersion = 1`, 마스터·Mask 사용 파일은 버전 2로 기록한다. 위치 주석은 GLIF lib의 `org.fontdraft.annotations`에 `{version: 1, items: [{id, x, y, text}]}`로 저장한다. 다른 편집기에서 주석 UI 재현은 보장하지 않는다. 브러시 설정·선택·화면 배율·Undo 이력은 UFOZ에 포함하지 않는다.

외부 파일도 위 범위라면 읽지만, 컴포넌트·2차 곡선·임의 외부 레이어 구성·커닝·features·앵커·이미지·외부 앱 주석·name 속성·제어점 식별자·기타 fontinfo/lib 데이터는 현재 지원하지 않는다. 발견하면 구체적인 항목을 표시하고 전체 열기를 중단하여 기존 작업을 유지한다. 앱 식별자만으로 호환된다고 판단하지 않는다. UFO 폴더 직접 열기는 아직 제공하지 않는다.

시제품 파일 한도: 압축 32MB, 전체 압축 해제 64MB, 개별 파일 8MB, ZIP 항목 10,000개. 한도를 넘으면 열기를 중단한다. 외부 편집기에서 변경한 파일은 지원 범위를 다시 검사한다.

- 실제 iPad Safari·Apple Pencil 검증은 미완료. 브라우저 입력 모사는 실기기 팜 리젝션이나 지연 검증을 대체하지 않는다.

## 스택

TypeScript + Vite + 일반 HTML/CSS + SVG. 런타임 UI 프레임워크는 없다. 곡선·면 연산에는 Paper.js 0.16.0(MIT), 브러시 단면의 합집합에는 polygon-clipping 0.15.7(MIT)을 사용한다. 편집 모델은 Paper 객체와 분리하고, 선택 밖 컨투어를 라이브러리 연산 결과로 덮어쓰지 않는다. UFOZ ZIP 처리에는 fflate 0.8.3(MIT)을 사용한다. 프로젝트 자동저장은 IndexedDB를 사용하며 서버에 업로드하지 않는다.

번들 크기는 `npm run build` 출력으로 확인한다. 기하 라이브러리를 포함한 다운로드 크기와 편집 중 연산 시간은 구분한다.

### 편집 UI 정리 (2026-10-26)

- 문자열 입력창은 툴바 위에 흰 배경·입력 테두리·포커스 표시로 구분한다. 비활성 글리프는 stroke 없이 fill만 보인다.
- 노드와 핸들은 독립적으로 선택 표시한다. 노드 선택만으로 연결 핸들을 선택하지 않으며, 세그먼트의 양 끝 노드와 선을 강조한다. 양 끝 노드가 모두 선택되면 그 사이 세그먼트도 강조한다. 컨투어 선택과 Cmd/Ctrl+A에도 동일하게 적용한다. 개별 핸들 선택은 유지한다.
- 글리프 정보는 오른쪽 패널에서 직접 편집한다. 별도 정보 모달은 제거하고 새 글리프 추가 모달만 유지한다. 입력칸은 32px로 줄이고 주변 라벨·버튼에 조작 여유를 둔다.

전체 선택 후 핸들을 드래그해도 선택을 유지한다. 핸들만 편집하려면 Escape 또는 빈 곳 탭으로 선택을 해제한 뒤 핸들을 선택한다. 최종 빌드와 Chrome 전체 52개 테스트 통과.

### 팔레트 편집 (2026-10-26)

- aside는 글리프·노드·브러시·변형의 독립 section으로 구분한다. 각 패널에 제목과 해당 조작만 둔다.
- 글리프 메트릭은 LSB / ADV / RSB 순서다. LSB 변경은 모든 윤곽선을 수평 이동하고 ADV를 함께 조정해 RSB를 보존한다. RSB 변경은 ADV만 조정하고, ADV 직접 변경은 윤곽선을 이동하지 않는다. 빈 글리프의 LSB·RSB는 비활성화한다.
- 메트릭은 입력을 확정할 때 반영하며 윤곽선과 폭을 하나의 Undo로 복원한다. 이름·Unicode는 입력 확정(포커스 이동 또는 Enter) 시 자동 적용한다. 메트릭 변경 중 작성 중인 이름·Unicode는 유지한다.
- 노드 또는 핸들 하나를 선택하면 X/Y 입력을 표시한다. 노드 좌표 수정은 연결 핸들도 함께 이동시키며, 핸들 좌표 수정은 독립적으로 적용한다. 복수 선택에서는 좌표를 숨긴다.
- 방향 버튼은 최소 52×52px의 ㅗ자 배치다. Shift·Opt·Delete와 함께 사이드 패널 스크롤에서 분리한 하단 고정 영역에 두며, 버튼 크기·테두리·아이콘·눌림 표시를 통일한다. 화면 Shift와 함께 누르면 10 units 이동한다.
- 변형 기준점은 3×3 버튼으로 고르며 각 터치 영역은 44×44px다. 기준 경계는 선택 노드와 독립 선택 핸들의 좌표 기준이다. 가로·세로 반전은 이 기준점을 사용한다. 완전히 선택된 닫힌 컨투어는 반전 후 와인딩을 유지해 구멍 관계를 보존한다. 부분 노드 반전은 선택 좌표만 변환한다.
- 면 합치기·빼기는 변형 패널 하단의 아이콘 버튼으로 제공하며 접근성 이름과 데스크톱 툴팁을 둔다.

화면 검토: 1194×834에서 글리프·노드 패널과 변형 패널 하단을 동시에 보려면 사이드바 스크롤이 필요하다. 아이콘의 의미를 설명하는 터치용 길게 누르기 도움말은 없고, 실제 iPad에서 숫자 입력 시 키보드가 차지하는 공간은 미검증이다. 후속 사용성 개선은 패널 접기와 터치 설명을 우선한다.

### iPad Safari 입력 수정 (2026-10-26)

- Pointer Events의 pointerType으로 pen/touch를 구분한다. 손가락으로 도구 사용은 기본 꺼짐이며 체크박스로 켤 수 있고 기기에 설정을 기억한다. 체크 여부와 무관하게 두 손가락은 캔버스 패닝·확대다. Pencil 입력 중의 캔버스 터치는 무시하며 Shift 조작은 별도로 받는다.
- 문서 자체는 고정하고 기본 확대·overscroll·텍스트 선택·길게 누르기 메뉴를 막는다. 팔레트·미리보기 등 지정 영역의 스크롤과 입력 필드의 텍스트 편집은 유지한다. Safari gesture 이벤트와 비수동 touch 이벤트로 브라우저 제스처를 차단하며 편집 제스처는 포인터 좌표로 계산한다.
- Shift는 별도 포인터를 캡처한다. 방향키는 click 합성을 기다리지 않고 pointerdown으로 처리하여 다른 손가락이 Shift를 잡고 있어도 동작한다.
- 상시 하단 상태바와 방향키 아래 1 unit 라벨을 제거한다. 상태바의 현재 도구·컨투어 수 정보는 중복이라 없애고 작업 오류·무효 연산 메시지만 일시적인 별도 표시 영역에 남긴다.
- smooth 노드는 초록 원형, corner는 파란 사각형으로 구분한다. 선택은 각 색의 채움으로 표시한다. 펜 드래그의 대칭 핸들 및 타원·기하 결과의 연속 접선에는 smooth 속성을 부여한다.
- 모든 노드·핸들 좌표를 정수로 반올림한다. 기존 프로젝트·UFOZ를 열 때도 전체 글리프에 적용하며 저장·내보내기에서도 유지한다. 주석 위치·글리프 폭·기준선 수치도 정수화한다. 정수 격자를 우선하므로 접선에 작은 반올림 오차가 생길 수 있다.
- 문자열·툴바·글리프 선택은 editor-chrome 안에, 실제 캔버스는 별도 canvas-surface 안에 둔다. 두 영역은 문서 흐름으로 배치하여 컨트롤이 그림 위에 떠 있지 않게 한다.
- 닫힌 컨투어 전체의 flip은 형상만 반전하고 와인딩을 보존한다. 이름·Unicode 적용 버튼은 제거했다. 유효하지 않은 입력은 저장하지 않고 인라인 오류를 표시한다.

검증 범위: Chrome의 네이티브 터치 이벤트 주입으로 두 손가락 패닝·확대, 페이지 배율 불변, 손가락 도구 opt-in, Shift+손가락 편집·방향키를 검사한다. WebKit 엔진에서는 단일 터치 opt-in과 편집·미리보기·팔레트·저장을 검사한다. WebKit 실행은 실제 iPad Safari나 Apple Pencil 하드웨어 검증을 대신하지 않는다.

## Opt 편집과 연산 개선 (2026-10-27)

- Opt 이동은 smooth 노드만 핸들 축선으로 제한한다. 일반 노드는 핸들이 일직선이거나 하나뿐이어도 자유롭게 이동하며, 핸들의 절대 위치는 유지한다.
- Opt 상태에서 핸들을 드래그하면 부모 노드를 두고 각도를 유지하며 길이만 바꾼다. 키보드 Option/Alt와 방향 버튼도 지원한다. 다시 Opt를 탭하거나 Esc로 해제한다.
- 기존 자료를 포함한 모든 노드·핸들 좌표는 정수화한다. 정수 격자를 우선하므로 대각선 각도에 작은 오차가 생길 수 있다.

## 필압·Worker·WASM (2026-10-27)

- 브러시의 **필압**은 기본 켜짐이다. 설정 크기가 최대 굵기이며 Pencil 압력 0–1에 따라 15–100%로 변한다. 타원 비율·각도는 유지한다. 체크를 끄거나 마우스/손가락으로 그리면 고정 굵기다. 지우개 필압은 기본 꺼짐이며 따로 켤 수 있다.
- 입력 중 가변 굵기를 바로 표시하고, 획 확정의 면 병합·곡선 피팅·지우개 연산은 전용 Worker에서 수행한다. 병합에는 Clipper2 WASM을 사용한다. WASM 바이너리를 읽지 못하면 Worker 안에서 JS 연산으로 대체한다.
- 다음 획을 계속 그리거나 패닝·확대할 수 있다. 대기 획은 순서대로 적용되며 각각 Undo된다. 처리 중 Undo는 마지막 대기 획을 취소하고 Esc는 대기 획 전체를 취소한다. 문서 편집·글리프 전환·저장은 대기 획이 끝날 때까지 잠시 비활성화한다.
- 새 윤곽의 짧은 세그먼트는 정수화 후 제한적으로 정리한다. 40개 합성 획에서 노드 4개를 줄였으나, 좌표가 겹치는 사례 1개는 보존 검사 때문에 남았다.
- 600점 가변 굵기 획의 워밍업 후 중앙값: Chrome JS 약 23ms / WASM 약 20ms, WebKit 31ms / 28ms. Worker 초기 로딩·데이터 전달·UI 확정을 포함한 총 지연 수치는 아니며 iPad 실측도 아니다. 초기 WASM은 약 214KB이고 별도 Worker 번들로 로드된다.

검증: Chrome 전체 91개, WebKit 관련 16개 통과(터치 주입 2개 제외). 배포 빌드의 Chrome/WebKit에서도 WASM Worker 실행 확인. 실제 iPad Safari + Pencil 필압 감도·연산 시간은 확인이 필요하다.

## 마스터와 Mask (2026-10-28)

오른쪽 팔레트 하단 **마스터 · Mask**에서 관리한다.

- 마스터는 프로젝트 전체에 공통이다. `+`는 모든 글리프가 빈 새 마스터, `복제`는 현재 마스터의 모든 글리프·자폭·주석·Mask 복사다. 이름 입력으로 이름을 바꾸고 마스터 목록의 행을 탭해 전환한다.
- 글리프 이름·Unicode·UPM은 공통이다. 윤곽·자폭·주석·기준선은 마스터별이다. `폰트 → 마스터 → 기준선`의 프로젝트 창에서 현재 마스터의 Ascender/Descender/x-height/Cap-height를 바꾼다.
- 각 마스터·글리프에는 전경과 Mask 하나가 있다. `전경`/`Mask`로 편집 대상을 전환하고 `Mask 표시`로 배경 윤곽을 숨길 수 있다. Mask 편집 시 전경을 참조 윤곽으로 보여준다. 전환해도 줌·패닝은 유지한다.
- `폰트 → Mask → 전경을 Mask로 복사`는 Mask를 교체한다. `Mask 붙여넣기`는 기존 전경을 보존하고 추가한다. 두 작업 모두 대상 레이어에서 Undo할 수 있다. Mask의 자폭은 전경과 공유한다. 하단 미리보기는 현재 편집 레이어(전경 또는 배경)를 따른다. 문자열 이미지 출력·글리프 썸네일은 전경만 사용한다.
- 편집 Undo/Redo는 마스터·글리프·전경/Mask별로 분리한다. Worker 작업 중에는 전환을 잠시 막고 결과의 대상 문맥도 확인한다. 마스터 삭제는 전체 글리프에 적용되므로 확인창을 거치며 Undo 대상은 아니다. 마지막 마스터는 삭제하지 못한다.
- UFOZ에 모든 마스터와 Mask를 보관한다. 기본 마스터 전경은 `public.default`, 기본 Mask는 UFO 표준 `public.background`, 추가 마스터의 전경·Mask는 별도 UFO 레이어다. 마스터 이름·기준선·연결은 `org.fontdraft.masters` lib 메타데이터다. 외부 에디터는 이를 일반 레이어로 볼 수 있으며 마스터/보간 구조의 자동 인식을 보장하지 않는다. 기존 단일 레이어 파일과 표준 public.background도 읽는다.

이번 범위는 마스터와 Mask 관리다. 임의 작업 레이어, 마스터 보간·가변축·Designspace 입출력은 포함하지 않는다.

검증: production build, Chrome 전체 98개 통과. 최종 화면 유지 보정 후 관련 17개, 정수화 중복 제거 후 저장·마스터 13개 재통과. WebKit 관련 17개 통과. fontTools 4.61.1 UFOReader에서 4개 레이어와 GLIF를 읽었다. 실제 iPad 팔레트 조작과 외부 GUI 편집기의 마스터 메타데이터 해석은 미검증이다.


## 메뉴와 겹침 도구

- 상단 **파일 / 편집 / 폰트 / 컨투어 / 보기**에서 명령을 선택한다. 마스터·Mask는 폰트 아래에 묶었고, 면 합치기·빼기와 가로세로 반전은 변형 팔레트에 있다.
- 편집 메뉴의 복사·잘라내기·붙여넣기·복제는 앱 내부 클립보드다. Cmd/Ctrl+C·X·V·D도 지원한다. 모든 글리프·마스터 사이에서 붙여넣을 수 있다. 일반 텍스트 입력은 시스템 클립보드를 사용한다.
- 글리프 복제는 모든 마스터·Mask·자폭을 복사하고 Unicode는 비운다. 글리프 삭제는 모든 마스터에 적용되며 마지막 글리프는 삭제할 수 없다.
- 컨투어 메뉴에서 시작점 설정, 방향 반전, 끊기·잇기, 겹침 제거·만들기, 모서리 루프를 실행한다. 시작 노드 자체를 삼각형으로 표시하며 꼭짓점은 다음 세그먼트로 나가는 접선 방향을 가리킨다. 닫힌 컨투어의 방향을 반전해도 시작 노드는 유지한다. 열린 경로는 시작·끝이 서로 바뀐다.
- **겹침 도구(나이프 오른쪽)**: 모서리 노드를 탭하면 양쪽을 24 units씩 연장한 채워진 루프를 만든다. 두 노드 사이를 드래그하면 분할된 각 조각의 기존 선분을 24 units씩 연장하고 닫아 겹침을 만든다. 직선 위의 불필요한 중간점은 제거해 턱을 만들지 않는다. 현재는 같은 닫힌 컨투어의 비인접 두 노드만 지원하며, 겹침 영역이 구멍 등 다른 컨투어와 만나면 적용하지 않는다.
- **편집 → 자유변형**: 사각 조절점으로 크기, 위쪽 원형 조절점으로 회전. Shift로 비율 유지, Esc 또는 다른 도구로 종료한다.
- **보기**에서 노드·핸들·기준선·메트릭·주석·Mask·글리프 목록·미리보기·사이드 패널을 켜고 끈다. 숨긴 노드·핸들은 직접 탭·마키 선택에서 제외한다.
- **전경과 Mask 교환**은 두 레이어를 한 번에 Undo한다. 교환 후 반대 레이어를 편집했다면 그 편집을 먼저 되돌려야 교환 Undo가 가능하다.

X-overlap·Ink Trap은 구현 범위에서 제외했다. Harmonize는 후순위다. 메뉴와 레이어 목록은 태블릿/좁은 화면에서 확인했지만 iPad Pencil 실기기 조작은 별도 확인이 필요하다. 팔레트가 길어 마스터 목록에는 세로 스크롤이 필요하다.

검증: production build 통과. Chrome 전체 107개 통과, WebKit 관련 32개 통과. Chromium 전용 CDP 멀티터치 주입 테스트 1개는 WebKit에서 제외했다. 실제 iPad/Pencil 입력 검증을 대체하지 않는다. 1194×834 및 390×844 화면에서 메뉴 배치와 가로 넘침을 확인했다.

선택 도구에서 Opt(또는 Alt)를 누르고 직선 세그먼트를 클릭하면 곡선 핸들 두 개가 생긴다. 펜 도구는 선에서 16 CSS px 이내를 클릭하면 해당 윤곽선 위에 노드를 추가한다. 노드 위에서는 삭제한다. 펜슬/마우스 hover 이벤트를 받으면 모든 도구의 커서를 표시하고 펜에는 추가 `+`·삭제 `−` 힌트를 표시한다. 브러시·지우개 단면 표시는 유지한다. 기기가 hover 위치를 보내지 않는 경우에는 펜을 대기 전 위치를 앱에서 알아낼 수 없다.

마스터 목록의 눈 아이콘을 켜면 해당 마스터의 현재 글리프가 편집 화면 뒤에 청회색 윤곽선으로 표시된다. 여러 마스터를 동시에 비교할 수 있으며, 현재 편집 중인 마스터는 항상 보인다. 참고 윤곽선은 편집·미리보기·이미지 출력에 포함하지 않는다. 표시 상태는 프로젝트와 UFOZ에 저장된다.

**컨투어 → 노드 복제**는 선택 노드 바로 뒤, 같은 컨투어의 같은 좌표에 점을 추가한다. 원본은 들어오는 핸들, 복제점은 나가는 핸들을 유지해 기존 모양을 보존한다. 복제점만 선택되므로 곧바로 이동할 수 있다. 별도 패스를 만드는 **편집 → 복제**와 구분한다.

## GitHub Pages 자동 배포

대상은 기존 `minw0525/minw0525.github.io` 저장소의 `/FontDraft/` 경로다. 기존 저장소를 clone한 뒤 이 프로젝트 소스를 그 안의 `FontDraft/`에 복사한다(`.git`, `node_modules`, `dist`, 테스트 출력 제외). 이 프로젝트의 `.github/workflows/deploy-pages.yml`은 대상 저장소 **루트**의 같은 경로에 둔다.

저장소 Settings → Pages → Source를 **GitHub Actions**로 지정한다. `main` push 또는 수동 실행 시 Node 22에서 `FontDraft/`를 빌드하고, 기존 사이트 파일을 `_site/`에 복사한 뒤 `FontDraft/` 자리에는 빌드 결과만 넣어 전체 사이트를 배포한다. 기존 루트 index.html·CNAME·다른 앱은 유지한다. 별도 `gh-pages` 브랜치나 수동 dist 업로드는 필요하지 않다.

현재 CNAME은 `parkminwoo.com`이므로 앱 경로는 `https://parkminwoo.com/FontDraft/`다. 실제 배포·저장소 연결은 별도 수행해야 한다. 이 단독 작업 폴더를 기존 사이트 저장소 루트에 덮어쓰지 않는다.

브라우저 프로젝트 저장소는 주소별로 분리되므로 localhost에서 작업한 문서는 UFOZ로 내보내 호스팅 주소에서 다시 연다.
