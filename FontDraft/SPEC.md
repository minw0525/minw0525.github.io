# FontDraft 구현 명세

상태: v0.7 / 2026-10-25 / 편집·주석·면 연산·프로젝트·자동저장·UFOZ 시제품 구현

이 문서의 ‘확정’은 대화에서 합의한 사항이다. ‘초기 가정’은 구현을 위한 제안이며, 검증 없이 사용자 확정 요구로 취급하지 않는다.

## 1. 제품과 범위

### 확정

- iPad 우선 웹앱. 향후 iPhone 등 작은 화면에서도 정밀 편집할 수 있는 방향을 유지한다.
- 프로젝트 → 글리프 추가·목록 → 글리프 편집창의 흐름.
- 자유 스케치 보드와 뼈대 브러시는 포함하지 않는다.
- 첫 버전의 파일 흐름은 새 프로젝트 생성과 이 앱에서 저장한 UFO 재열기다.
- 프로젝트 파일은 `.ufoz`. 설치 가능한 OTF/TTF 생성은 제외한다.
- 검증 기기: iPad Pro 11-inch (4th generation), Wi-Fi / iPadOS 26.6.1 / Apple Pencil 2세대. 사용자 제공 환경이며 아직 실기기 검증하지 않았다.

### 초기 가정

- 프로젝트 공통 마스터와 마스터·글리프별 전경/Mask를 관리한다. 이름·Unicode·UPM은 공통이며 자폭·윤곽·주석·기준선은 마스터별이다.
- 로그인 없이 기기 내 자동 저장을 제공하며, 파일 내보내기는 별도로 제공한다.
- SVG와 PNG는 공유용 내보내기 후보이며 프로젝트 저장의 대체물이 아니다.
- 클라우드 동기화, 실시간 공동 편집, 가변축, 커닝, OpenType 조판은 첫 버전에서 제외한다.
- UI는 React 없이 TypeScript·Vite·일반 HTML/CSS·SVG로 구현한다. 기하 연산에는 Paper.js 0.16.0(MIT)을 시제품에 채택했다. ZIP 처리는 fflate 0.8.3(MIT)을 채택했다.

## 2. 편집 모델

프로젝트는 공통 글자 기준과 글리프 목록을 갖는다. 글리프는 이름, 선택적 문자 매핑, 글자 폭, 컨투어, 주석을 갖는다.

- 컨투어는 열린/닫힌 상태와 순서 있는 노드·곡선 정보를 갖는다.
- 구멍을 포함하는 별도 ‘도형 객체’는 선택 단위로 도입하지 않는다.
- 면 표시는 non-zero 와인딩 규칙을 기준으로 한다. 컨투어의 중첩만으로 구멍이라고 판정하지 않는다.
- 뼈대·브러시 파라미터를 유지하는 라이브 객체는 없다. 확정된 획은 윤곽선이다.
- 브러시 설정을 바꿔도 기존 획은 다시 생성하지 않는다.
- 열린 컨투어는 편집용 선으로 표시하고 채움 및 지우개 연산에서 제외한다.

초기 가정: 신규 작성은 직선과 3차 베지어로 시작한다. UFO에서 읽을 수 있는 곡선 종류의 범위는 구현 전에 명시한다. 미지원 곡선을 몰래 근사하거나 버리지 않는다.

선택 상태, 화면 확대·이동, 입력 중 미리보기는 윤곽선 데이터와 구분한다. 지우개·나이프 등으로 컨투어 수가 바뀔 수 있으므로 배열 인덱스를 영구 식별자로 사용하지 않는다.

## 3. 도구와 입력

도구 범위: 선택, 펜, 면 브러시, 면 지우개, 기초도형(사각형·타원), 나이프, 회전, 크기 조정, 기울이기, 주석.

초기 가정: 회전·크기 조정·기울이기는 선택 시 변형 패널로 제공한다. 독립 도구 버튼으로 노출할지는 시제품에서 결정한다. 주석은 우선 위치에 연결된 텍스트다.

변형 시제품: 선택 도구의 오른쪽 패널에서 수치 입력 후 적용한다. 기준점은 선택 노드 좌표 경계 상자의 9개 점(기본은 중심)이다. 선택한 노드와 해당 핸들에 동일한 아핀 변환을 적용하고 다른 노드는 보존한다. 회전은 −360~360도, 크기는 축별 1~1000%, 수평 기울이기는 −80~80도다. 크기는 비율 잠금을 기본으로 제공한다. 한 번 적용을 Undo 한 단계로 기록한다. 직접 드래그하는 변형 핸들과 사용자 지정 기준점은 아직 제공하지 않는다.

### 선택 — 확정

- 선택 도구의 기본은 노드 편집이다. 컨투어 선택 모드에 먼저 들어갈 필요가 없다.
- 노드·핸들 탭/드래그로 선택·이동한다.
- 노드 더블탭은 smooth를 전환한다. 세그먼트 더블탭은 해당 컨투어의 모든 노드를 선택한다. 모든 핸들을 표시하며 핸들과 세그먼트도 독립적으로 다중 선택한다. 선택된 노드는 다른 노드보다 위에 표시한다.
- 안쪽 구멍과 다른 컨투어를 자동으로 함께 선택하지 않는다.
- modifier를 사용해 선택을 추가·해제할 수 있게 한다.

초기 가정:

- 히트 마진은 글리프 좌표가 아닌 화면 거리 기준으로 유지한다. 구체적인 크기는 실기기에서 정한다.
- 여러 컨투어의 노드가 후보이면 화면상 가장 가까운 노드를 우선한다. 동률의 처리 순서는 결정적으로 유지한다.
- 노드 히트 마진 밖의 면 더블탭은 컨투어 전체 선택으로 해석하지 않는다.
- 빈 곳 탭으로 선택을 해제한다.
- 나이프의 노드 탭과 선택 도구의 더블탭은 활성 도구에 따라 구분한다.

시제품 값: 히트 반경 14 CSS px, 드래그 시작 거리 4 CSS px, 같은 대상의 더블탭 간격 340ms, 세그먼트 히트 반경 10 CSS px. modifier는 화면 ⇧ 버튼과 물리 Shift로 시험한다. 영역 선택과 1 unit 미세 이동을 제공한다. 이 수치는 iPad에서 아직 검증하지 않았다.

### modifier — 확정

- 보조 손으로 누르는 오버레이를 제공한다. 오른쪽 선택 패널에 ⇧를 두며 방향키·미세 이동 버튼과 함께 누르면 10 units 이동한다.
- 나이프에 별도 ‘점 추가 / 면 분할’ 선택 단계를 넣지 않는다.
- 드래그 시작 시 modifier 상태로 동작을 결정한다. 도중에 손이 떨어져도 해당 드래그의 의미는 유지한다.
- 현재 동작을 표시와 미리보기로 구분한다.

초기 가정: 펜슬은 현재 도구, 두 손가락은 화면 이동·확대에 사용한다. modifier 위에서 시작한 터치는 캔버스 제스처에 포함하지 않는다. 펜슬 입력 중 손바닥 접촉과 화면 이동의 우선순위는 실기기에서 검증한다.

시제품 입력 정책: 펜슬 입력 중 새 캔버스 터치는 무시하되 modifier 터치는 허용한다. 손가락 편집 도중 두 번째 손가락이 닿으면 편집을 복원하고 확대·패닝으로 전환한다. pointercancel·예상하지 못한 capture 상실·창 비활성화·화면 크기 변경은 진행 중 편집을 취소한다. 드래그 한 번은 Undo 한 단계이며 최근 100단계를 메모리에 유지한다.

### 면 브러시 — 확정

- 펜촉 속성은 크기, 타원의 납작함, 각도다.
- 필압을 끄면 크기는 한 획 전체에서 하나의 값을 사용한다. 필압을 켜면 설정 크기를 최대값으로 사용한다.
- 결과는 면이며, 이후 외곽선 노드로 편집한다. 뼈대 편집 기능은 없다.
- 참고 이미지의 조작 개념을 참고하되 UI를 그대로 이식하지 않는다.

초기 가정:

- 크기는 타원 장축 지름, 납작함은 단축/장축 비율로 정의한다.
- 각도는 글리프 좌표 기준 고정값이며 진행 방향을 따라 자동 회전하지 않는다.
- 필압은 크기에만 반영하며 납작함·각도는 유지한다. 2026-10-27 가변 굵기 구현으로 초기 고정 크기 제한을 변경했다.
- 각 획은 기존 컨투어와 자동 병합하지 않는다. 한 획의 자기 겹침은 정리한다.
- 신규 획의 방향은 일관되게 정해 겹쳐 그릴 때 의도하지 않은 구멍이 생기지 않게 한다.

시제품 구현: 입력점을 타원 펜촉의 역변환 좌표로 옮긴 뒤 반지름 1의 연속 캡슐 영역을 합치고, 다시 펜촉 변환을 적용한다. 입력점 사이를 연결하므로 빠른 입력에서도 독립적인 도장 사이의 빈틈이 생기지 않는다. 입력 중 가변 반지름의 접선 스윕을 SVG로 미리보기하고 획 종료 시 Worker에서 실제 윤곽선을 계산한다. 이동 1.5 CSS px 미만이고 필압 변화 0.02 미만인 입력은 생략한다. 단면은 인접 구간에서 정확히 공유하는 64각형으로 합치며 이후 곡선 피팅한다. 단순화는 기본 3 units, 사용자 설정 0–12이며 0은 끄기다. 양방향 표본 거리·방향·새 교차를 검사하고 허용하지 못하는 결과는 원래 경계를 유지한다. 고급 획 안정화와 실기기 성능 검증은 남아 있다. 브러시·지우개 커서에 타원 단면을 표시한다.

### 지우개 — 확정

| 상태 | 연산 |
| --- | --- |
| 선택 있음 | 선택한 컨투어들만으로 면을 계산하고 지우개 영역을 차감한다. 선택 밖 컨투어는 수정하지 않는다. |
| 선택 없음 | 글리프의 보이는 면을 기준으로 차감한다. 필요한 컨투어는 병합·분리될 수 있다. |
| 열린 컨투어 | 연산에서 제외한다. |
| 연산과 무관한 컨투어 | 불필요하게 병합하거나 재작성하지 않는다. |

- `o`를 C 형태로 자르려면 안팎 컨투어를 함께 선택하거나 선택을 해제하고 지운다.
- 바깥만 선택한 경우, 안쪽을 자동으로 연산 대상에 넣어 C를 만들지 않는다.
- 선택하지 않은 면이 겹쳐 있으면 지운 부분을 덮어 여전히 검게 보일 수 있다. 이는 선택 범위를 지킨 결과다.
- 한 지우개 획은 하나의 Undo 단계다.
- 전체 면 차감 결과를 기존 컨투어 구분대로 복원하는 기능은 첫 버전에서 구현하지 않는다.

초기 가정: 노드 일부만 선택되어 있으면 선택된 노드가 속한 닫힌 컨투어 전체를 지우개 대상으로 한다. 열린 컨투어만 선택되어 있으면 아무 면도 지우지 않으며, ‘선택 없음’으로 바꿔 전체에 적용하지 않는다. 이 범위 규칙은 시제품에서 사용자 확인이 필요하다.

위 초기 가정으로 시제품을 구현했다. 교차 또는 포함 관계가 있는 대상 컨투어들을 묶어 non-zero 면 차감을 수행한다. 실제 제거되는 면적이 없으면 기존 컨투어를 그대로 반환한다. 변경 대상이 아닌 컨투어는 ID·노드·좌표를 보존한다. 선택 모드에서는 연산으로 새로 생긴 컨투어들을 다음 지우개 획에서도 대상으로 삼도록 선택한다.

‘무관한 컨투어’ 여부는 단순히 지우개와 직접 교차했는지만으로 결정하지 않는다. 보이는 면을 구성하는 중첩·구멍 관계 때문에 연산에 필요한 컨투어는 포함할 수 있다. 단, 선택 모드에서는 선택 밖 컨투어를 수정할 수 없다.

초기 가정: 지우개도 크기·납작함·각도를 지원하되 브러시와 설정을 따로 기억한다.

### 나이프 — 확정

| 조작 | 결과 |
| --- | --- |
| 기본 드래그 | 교차 위치마다 노드를 추가한다. 곡선 모양과 면은 유지한다. |
| modifier + 드래그 | 닫힌 조각을 만들 수 있는 구간에서 면을 분할한다. |
| 기존 노드 탭 | 윤곽선을 끊는다. |

- 교차 개수로 점 추가와 면 분할 모드를 자동 전환하지 않는다.
- 같은 세그먼트와 여러 번 교차할 수 있다. 교차점은 모두 처리한다.
- 기존 꼭짓점에서 중복 교차·중복 노드를 만들지 않는다.
- 면에 스치기만 하는 접촉은 면을 관통한 절단으로 처리하지 않는다.
- 닫힌 컨투어의 노드 탭: 같은 위치의 시작점·끝점으로 열린 컨투어를 만든다.
- 열린 컨투어의 내부 노드 탭: 두 열린 컨투어로 나눈다. 이미 열린 끝점 탭은 변경하지 않는다.
- 한 동작은 하나의 Undo 단계다.

초기 가정:

- 절단선은 드래그 시작점과 끝점을 잇는 직선이다.
- 면 분할 모드에서 불완전한 관통은 점 추가로 자동 대체하지 않는다. 유효한 분할 구간만 처리한다.
- 열린 컨투어에는 기본 드래그의 점 추가만 적용하고 면 분할은 적용하지 않는다.
- 나이프 드래그는 지우개와 동일하게 선택이 있으면 선택한 노드가 속한 컨투어들, 없으면 전체를 대상으로 시제품을 구현했다. 노드 탭은 직접 탭한 노드에 적용한다. 이 범위 규칙은 사용자 확인이 필요한 초기 가정이다.

나이프 시제품 구현:

- 기본 드래그는 교차점의 베지어 매개변수로 곡선을 나눈다. 기존 노드 ID를 유지하고 필요한 노드만 추가한다. 동일 곡선의 다중 교차는 역순으로 분할한다.
- 면 분할은 완전히 포함된 반대 와인딩 구멍만 묶고, 겹쳐 있는 별도 컨투어는 각각 처리한다. 절단되지 않은 컨투어는 그대로 보존한다. 대상의 non-zero 경계를 계산하고, 드래그 선분 안의 유효한 교차점 쌍에 서로 반대인 절단 경계를 추가한다. 선분을 무한 직선으로 연장하지 않는다.
- 구멍과 외부를 연결하는 절단은 경계를 하나로 연결하며, 면 전체 관통은 여러 닫힌 조각을 만든다. 절단 폭은 0이므로 실루엣은 그대로이며 이후 조각을 이동해서 분리를 확인할 수 있다.
- 홀수 교차에서는 완전히 관통한 구간만 자른다. 불완전한 구간에 노드 추가 동작을 대신 수행하지 않는다.
- 미리보기는 기본 모드의 파란 점선·교차점, 면 분할 모드의 주황 실선·교차점으로 구분한다. 실제 연산과 선택 변경은 포인터를 뗄 때 확정한다.

### 면 합치기·빼기

- 빼기 대상 규칙은 사용자 확정: 선택한 노드가 속한 컨투어들을 칼날로 삼아 나머지 컨투어에서 뺀다. 버튼 뒤 추가 탭이나 선택 순서에 의존하지 않는다.
- 시제품 합치기는 선택된 닫힌 컨투어가 만드는 non-zero 면을 정리한다. 반대 방향의 내부 컨투어는 구멍으로 남고, 선택 밖 컨투어와 떨어진 컨투어는 보존한다.
- 빼기는 선택한 닫힌 컨투어들의 non-zero 면을 칼날로 쓴다. 차감이 발생하면 선택 칼날 전체를 소비하며, 실제 겹침이 전혀 없으면 변경하지 않는다. 열린 컨투어와 차감에 영향 없는 컨투어의 ID·좌표는 유지한다. 여러 칼날의 내부 구멍도 보존한다.
- 노드 일부만 선택해도 해당 컨투어 전체를 대상으로 한다. 선택 없는 합치기·빼기는 실행하지 않는다. 결과 노드를 선택하며 각 연산은 Undo 한 단계다.

### 위치 주석

- 주석 도구로 탭한 글리프 좌표에 인라인 텍스트박스를 만든다. 박스는 계속 표시하며 내용을 직접 수정하고 ×로 삭제한다. XY 모달은 없다.
- 패닝·확대 시 글리프 위치를 따라가고 검은 면 미리보기에서는 숨긴다. 텍스트는 최대 2,000자이며 포커스를 벗어나거나 작업을 전환할 때 확정한다. 빈 새 주석은 만들지 않고 기존 주석을 비우면 삭제한다.
- 추가·수정·삭제는 글리프별 Undo 이력에 포함한다. 면 연산·노드 변형은 주석에 영향을 주지 않는다.
- 자동저장과 UFOZ에 포함하며, 주석 없는 기존 프로젝트도 그대로 연다. 미지원 주석 버전·중복 ID·잘못된 좌표·미지원 필드는 거부한다.

## 4. 저장과 복구

### 확정

- 파일은 표준 UFO 3 구조의 `.ufoz`다. ZIP의 확장자만 `.ufo`로 바꾸지 않는다.
- 이 앱에서 저장한 파일은 글리프 이름·문자 매핑·폭·컨투어·열린 경로를 복원해야 한다.
- UFO의 사용자 정의 데이터 영역에 앱 식별 정보와 저장 구조 버전을 넣을 수 있다.
- 앱 식별 표시는 호환성 보증이 아니다. 실제 파일 구조와 기능을 검사한다.
- 외부 UFO도 지원 범위 내 데이터면 허용할 수 있지만, 임의 외부 UFO 완전 호환은 첫 버전 보장 사항이 아니다.
- 미지원 데이터를 조용히 삭제하거나, 불완전하게 읽은 결과로 원본을 덮어쓰지 않는다.

초기 가정:

- 주석 등 앱 전용 정보는 이름 공간을 둔 lib 데이터에 저장한다. 정확한 키는 구현 단계에서 정한다.
- 기기 내 자동 저장과 내보낸 파일을 구분한다. 저장 실패를 성공으로 표시하지 않는다.
- 입력 취소·앱 전환 시 미확정 동작은 취소하고 마지막 확정 데이터를 유지한다.
- 편집 중에는 내부 모델을 사용하고 파일 저장 시 UFO로 직렬화한다. 매 포인터 이벤트마다 ZIP을 다시 만들지 않는다.
- UFO 폴더 가져오기는 iPad 파일 선택 동작을 확인한 뒤 지원 여부를 정한다. 우선 `.ufoz` 재열기를 보장한다.

### 현재 구현 범위

- 기본 전경, public.background 및 앱 마스터 레이어의 UFO 3.0 / GLIF 2.0. 직선과 3차 베지어, 열린/닫힌 경로, 컨투어·노드 ID와 smooth 속성, 글리프 이름·순서·복수 문자 매핑·폭을 저장한다. 열린 경로 끝의 사용하지 않는 핸들은 확정 시 제거한다.
- familyName, styleName, unitsPerEm, ascender, descender, xHeight, capHeight를 프로젝트 정보로 저장한다. UPM 변경은 윤곽선을 리스케일하지 않는다.
- lib의 `org.fontdraft.formatVersion`은 단일 전경 파일 1 / 마스터·Mask 파일 2, `public.glyphOrder`는 글리프 순서다. 주석은 GLIF lib의 `org.fontdraft.annotations`에 버전 1과 items 배열(id, x, y, text)로 저장한다. 임의 속성을 복원한다고 주장하지 않는다.
- 컴포넌트, 2차 곡선, 임의 외부 레이어 구성, 앵커, 이미지, 커닝, features, 미지원 fontinfo/lib 키와 GLIF 속성은 열기를 거부한다. 지원 범위를 벗어난 데이터는 자동 삭제·근사하지 않는다. 원본 파일은 덮어쓰지 않고 다운로드로만 내보낸다.
- 신규 프로젝트는 UPM 1000, ascender 800, descender −200, x-height 500, cap-height 750, 이름 Unititled, 빈 A 글리프(폭 600)로 시작한다. 첫 실행도 동일하다. 문자들을 입력해 Unicode를 자동 지정하고 공통 폭으로 일괄 추가한다.
- 프로젝트별 확정 상태를 IndexedDB에 저장하고 마지막 프로젝트·글리프를 복원한다. 자동저장 실패를 표시하고 UFOZ 저장은 계속 사용할 수 있다. 자동저장은 주소·브라우저에 종속된다.
- Undo/Redo는 현재 세션의 글리프별 윤곽선·주석 이력이며 파일/새로고침으로 복원하지 않는다. 프로젝트·글리프 메타데이터 변경은 이 이력에 포함하지 않는다.
- 파일 열기는 전체 검증 후 새 프로젝트로 추가한다. 새 프로젝트 생성도 기존 프로젝트를 보존한다. 파일 작업·글리프 전환 시 유효한 펜 초안은 열린 경로로 확정한다.
- ZIP 제한은 압축 32MB, 해제 총합 64MB, 파일당 8MB, 항목 10,000개다. 폴더 경로 이탈·누락 파일·중복 ID·비유한 좌표·잘못된 문자 코드를 거부한다.

## 7. 화면과 미리보기 (2026-10-25)

- 편집 면은 연회색, 검은 면 미리보기에서는 노드·핸들·가이드·주석을 숨긴다. 표시 모드 전환은 편집 데이터·Undo·선택·펜 초안을 변경하지 않는다. 미리보기는 표시만 바꾸며 도구·선택·modifier·편집 명령을 그대로 유지한다. 현재 편집 레이어를 검은 면으로 표시하고, 입력 중 도구 미리보기·커서·자유변형 조절점과 주석 도구의 텍스트 입력은 계속 표시한다.
- 편집 공간의 미리보기와 독립된 하단 실시간 패널을 제공한다. 편집 문자열에 배치된 글리프의 확정된 닫힌 컨투어만 non-zero 검은 면으로 렌더링한다. 노드 드래그 중에도 갱신한다.
- 패널 크기는 48–360 px/em, 초기 120 px/em. 높이는 경계 드래그 또는 포커스 후 방향키로 조절한다. 접기와 펼치기는 문서에 저장하지 않는 화면 상태다. 패널 변동 시 편집 영역 중심을 유지하며 좌표는 바꾸지 않는다.
- 중성 회색 UI, 얇은 패널 구분선, 일관된 SVG 아이콘을 사용한다. 참조는 사용자가 첨부한 Glyphs·FontLab 화면이며 미구현 기능을 장식 버튼으로 추가하지 않는다.

## 8. 문자열 편집과 메트릭 (2026-10-26)

- 편집 문자열의 각 글리프를 자폭 순서로 배치하고 비활성 글리프 더블탭으로 활성화한다. 활성 노드 더블탭은 smooth, 활성 세그먼트 더블탭은 컨투어 선택이다.
- 없는 문자는 자리표시자로 나타내고 더블탭하면 문자 추가 창을 연다. 커닝·조판은 하지 않는다. 문자열과 활성 슬롯은 파일에 저장하지 않는 화면 상태다.
- 상단 가로 툴바를 두어 왼쪽 기준선 라벨을 가리지 않는다. 기준선에는 테두리 없이 숫자만 표시하고 LSB·폭·RSB 위젯은 테두리로 구분한다. 자폭에는 ADVW 접두어를 붙이지 않는다. LSB/RSB는 실제 곡선 경계로 계산한다.
- 사각형·타원은 시작 시 ⇧로 정방형을 고정하고 드래그 중 채움 없이 stroke만 표시한다.

### 편집 UI 정리 (2026-10-26)

- 문자열 입력창은 툴바 위에 흰 배경·입력 테두리·포커스 표시로 구분한다. 비활성 글리프는 stroke 없이 fill만 보인다.
- 노드와 핸들은 독립적으로 선택 표시한다. 노드 선택만으로 연결 핸들을 선택하지 않으며, 세그먼트의 양 끝 노드와 선을 강조한다. 양 끝 노드가 모두 선택되면 그 사이 세그먼트도 강조한다. 컨투어 선택과 Cmd/Ctrl+A에도 동일하게 적용한다. 개별 핸들 선택은 유지한다.
- 글리프 정보는 오른쪽 패널에서 직접 편집한다. 별도 정보 모달은 제거하고 새 글리프 추가 모달만 유지한다. 입력칸은 32px로 줄이고 주변 라벨·버튼에 조작 여유를 둔다.

### 팔레트 편집 (2026-10-26)

- aside는 글리프·노드·브러시·변형의 독립 section으로 구분한다. 각 패널에 제목과 해당 조작만 둔다.
- 글리프 메트릭은 LSB / ADV / RSB 순서다. LSB 변경은 모든 윤곽선을 수평 이동하고 ADV를 함께 조정해 RSB를 보존한다. RSB 변경은 ADV만 조정하고, ADV 직접 변경은 윤곽선을 이동하지 않는다. 빈 글리프의 LSB·RSB는 비활성화한다.
- 메트릭은 입력을 확정할 때 반영하며 윤곽선과 폭을 하나의 Undo로 복원한다. 이름·Unicode는 입력 확정(포커스 이동 또는 Enter) 시 자동 적용한다. 메트릭 변경 중 작성 중인 이름·Unicode는 유지한다.
- 노드 또는 핸들 하나를 선택하면 X/Y 입력을 표시한다. 노드 좌표 수정은 연결 핸들도 함께 이동시키며, 핸들 좌표 수정은 독립적으로 적용한다. 복수 선택에서는 좌표를 숨긴다.
- 방향 버튼은 52×52px의 ㅗ자 배치다. 화면 Shift와 함께 누르면 10 units 이동한다.
- 변형 기준점은 3×3 버튼으로 고르며 각 터치 영역은 44×44px다. 기준 경계는 선택 노드와 독립 선택 핸들의 좌표 기준이다. 가로·세로 반전은 이 기준점을 사용한다. 완전히 선택된 닫힌 컨투어는 반전 후 와인딩을 유지해 구멍 관계를 보존한다. 부분 노드 반전은 선택 좌표만 변환한다.
- 면 합치기·빼기는 변형 패널 하단의 아이콘 버튼으로 제공하며 접근성 이름과 데스크톱 툴팁을 둔다.

화면 검토: 1194×834에서 글리프·노드 패널과 변형 패널 하단을 동시에 보려면 사이드바 스크롤이 필요하다. 아이콘의 의미를 설명하는 터치용 길게 누르기 도움말은 없고, 실제 iPad에서 숫자 입력 시 키보드가 차지하는 공간은 미검증이다. 후속 사용성 개선은 패널 접기와 터치 설명을 우선한다.

### iPad Safari 입력 수정 (2026-10-26)

## 터치 히스토리 (2026-10-27)

캔버스에서 두 손가락을 짧게 탭하면 Undo, 세 손가락이면 Redo다. 최초 접촉부터 마지막 해제까지 350ms 미만이고 각 손가락 이동이 10 CSS px 이하여야 한다. 마지막 손가락을 뗄 때 한 번 실행하며 탭 중 발생한 미세한 뷰 이동은 복원한다. 네 손가락 이상, 취소, 패닝·확대 및 길게 누르기는 히스토리를 실행하지 않는다. Shift 버튼의 터치는 세지 않으며 손가락 도구 사용 설정과 무관하다. 정상 pointerup 이후 capture 해제는 남은 손가락의 제스처를 취소하지 않는다.

## Opt 축선 편집과 정수 좌표 (2026-10-27)

- 선택 패널의 Opt는 Shift와 같은 짧은 탭 고정/해제 및 누른 채 조작을 제공한다. 키보드 Option/Alt도 지원한다. 드래그 시작 시 화면 Opt 상태를 고정하며 방향 버튼에도 적용한다.

FontLab의 핸들 방향 고정은 Shift지만 이 앱은 요청대로 Opt로 통일했다.

## 브러시·지우개 연산 개선 (2026-10-27)

## 비동기 기하 엔진 (2026-10-27)

- 브러시 필압 기본 켜짐, 지우개 기본 꺼짐. 배율 = 0.15 + 0.85 × pressure. mouse/touch는 필압 없는 고정 크기이며 pointerup의 0 압력으로 끝을 강제 축소하지 않는다. 압력 미지원 pen의 상수 0.5는 장치 지원으로 오인하지 않으며 사용자가 필압을 끌 수 있다.
- coalesced 포인터 입력을 수집하고 위치 오차 + 반지름 보간 오차로 축약한다. 직선 위에서도 압력 변곡은 보존한다. 미리보기 갱신은 requestAnimationFrame으로 제한한다.
- Worker 한 개에서 획을 직렬 처리한다. Clipper2 WASM은 정규화된 펜촉 스윕의 NonZero union을 소수점 6자리로 계산한다. Paper 곡선 피팅·지우개·보존 검사는 같은 Worker 안의 JS로 수행한다. WASM은 BSL-1.0이며 라이선스는 THIRD_PARTY_NOTICES.md에 둔다.
- 작업 ID와 큐 객체를 대조해 오래된 응답을 폐기한다. 문서 적용 시 프로젝트/글리프 ID도 확인한다. 다음 획·패닝 중 도착한 응답은 현재 제스처가 끝난 뒤 적용한다. 각 획마다 그 직전 결과를 기준으로 한 Undo 스냅샷을 만든다.
- Undo는 마지막 대기 획을 취소한다. 실행 중인 마지막 작업 취소 시 Worker를 terminate하고 다음 요청에서 재생성한다. Esc는 현재 제스처와 대기 획 전체를 취소한다. 처리 중 저장·문서 변경을 막아 미확정 결과가 저장에서 빠지거나 다른 글리프에 적용되지 않게 한다.
- WASM fetch 실패는 Worker 내부 JS union으로 대체한다. Worker 로드/실행 실패는 큐를 비우고 기존 문서를 유지하며 오류를 알린다. 메인 스레드에서 무거운 연산으로 재시도하지 않는다.
- 새 윤곽만 정수화 후 짧은 세그먼트를 정리한다. 길이 3 units 이하의 곡선을 합치는 후보에 대해 원본 대비 양방향 표본 오차 ≤ min(0.75, simplify/4), 자기교차·와인딩·다른 컨투어와의 교차/포함 관계를 검사한다. 후보도 정수화한 상태로 검사해 재반올림으로 오차가 늘지 않게 한다. 기존 지우개 비접촉 컨투어는 보존한다. 표본 검사는 수학적 최대 오차 증명이 아니다.
- 워밍업된 600점 가변 획 비교: Chrome JS 약 23ms / WASM 약 20ms, WebKit 31ms / 28ms. 비교는 동일 기하 함수의 연산 시간이며 Worker 초기화/전달/UI 적용은 별도다. 40개 합성 획의 정리 비용 합계 Chrome 약 75ms, WebKit 144ms. 노드 4개 제거, 같은 좌표 사례 1개 유지.

## 마스터·Mask (2026-10-28)

프로젝트의 기본 마스터는 기존 글리프 데이터와 기준선을 그대로 사용해 과거 IndexedDB/UFOZ와 호환한다. 추가 마스터는 안정적인 ID와 이름, 네 기준선, 글리프 ID별 Drawing을 가진다. Drawing은 자폭·전경 윤곽/주석·선택적 Mask 윤곽/주석이다. 전경과 Mask는 자폭을 공유한다. 새 글리프는 모든 마스터에 존재하되 각 윤곽은 빈 상태에서 시작한다.

- 새 마스터는 현재 기준선·자폭을 바탕으로 빈 전경을 생성한다. 복제는 모든 글리프와 Mask를 깊은 복사한다. 삭제 시 마지막 마스터를 보호하며 기본 마스터 삭제는 다음 마스터를 기본으로 승격한다. 마스터 이름은 프로젝트 안에서 고유하다.
- 마스터 선택과 전경/Mask 편집 모드는 프로젝트에 저장한다. 전환 전에 현재 초안·주석을 정리하고 해당 문맥의 Undo를 저장한다. Undo 키는 프로젝트/마스터/글리프/레이어로 구성한다. 화면 좌표계는 유지한다.
- 선택·나이프·지우개·노드 편집은 활성 레이어에만 작용한다. 반대 레이어는 비선택 참조 윤곽이다. 하단 미리보기는 활성 마스터의 현재 편집 레이어를 따른다. 배경 편집 중에는 문자열의 각 글리프 배경을 표시하며 빈 배경은 비워 둔다. 이미지 출력은 활성 마스터의 전경을 사용한다.
- 복사 명령은 대상 레이어를 교체하고 그 대상의 Undo 한 단계로 기록한다. 마스터 추가·삭제·이름·기준선 변경은 윤곽 편집 Undo에 포함하지 않는다. 삭제 전 명시적 확인창을 표시한다.
- Worker 큐는 프로젝트/마스터/글리프/레이어를 확인한 후 반영한다. 대기 연산 중 레이어·마스터 전환은 막는다. 저장은 모든 마스터·Mask를 정수화해 보관한다.
- 단일 UFO에는 네이티브 마스터 구조가 없으므로 모든 윤곽을 표준 GLIF 레이어에 쓰고 `org.fontdraft.masters`에 추가 마스터 ID/이름/기준선/전경 레이어명/배경 레이어명, 기본 이름, 활성 마스터, Mask 편집·표시 상태를 기록한다. fontinfo는 기본 마스터 기준선이다. public.background의 역할은 [UFO 표준](https://unifiedfontobject.org/versions/ufo3/layercontents.plist/)을 따른다.
- import는 중복 레이어명·디렉터리·마스터 ID/이름, 누락된 레이어/글리프, 잘못된 활성 마스터·기준선, 미지원 추가 파일을 거부한다. 표준 public.background의 자폭은 전경과 같거나 0일 때 공유 자폭으로 읽는다. 다른 자폭이나 레이어별 Unicode 차이는 보존할 수 없으므로 거부한다. 임의 외부 마스터/레이어 구성은 자동 추측하지 않는다.

### 카테고리 메뉴와 컨투어 명령

상단은 파일·편집·폰트·컨투어·보기 메뉴로 구성한다. 마스터와 Mask는 폰트 메뉴의 하위 목록이다. 항목은 최소 44px 높이이며 바깥 탭/Esc로 닫힌다. 면 합치기·빼기와 가로세로 반전은 변형 팔레트에 둔다.

Mask 붙여넣기는 기존 전경을 보존하고 새 ID로 추가한다. 전경을 Mask로 복사는 Mask 교체이다. 교환은 현재 마스터·글리프의 두 레이어만 교환하며 한 번의 Undo/Redo로 복원한다. 교환 이후 반대 레이어 편집이 남아 있으면 그 편집을 먼저 되돌려야 교환 Undo가 가능하다. 글리프 복제는 모든 마스터·Mask·자폭을 복제하되 Unicode를 비운다.

컨투어의 첫 노드 자체를 삼각형으로 표시한다. 별도의 옆 표시는 두지 않고 smooth/corner 색과 선택 채움 규칙을 그대로 적용한다. 삼각형 꼭짓점은 다음 세그먼트의 출발 접선을 따른다. 길이가 0인 핸들은 다음 제어점으로, 퇴화 세그먼트는 다음 유효 세그먼트로 건너뛴다. 닫힌 컨투어의 방향 반전과 반전 변형의 winding 보정은 시작 노드를 유지한다. 열린 경로의 방향 반전은 시작·끝을 교환한다. 시작점 설정은 노드 순서만 회전하며 모양을 바꾸지 않는다. 잇기는 열린 경로 끝점 두 개에 적용하고 같은 좌표의 끝점은 합친다.

겹침 도구의 노드 탭은 Loop Corner이다. 양쪽 접선 방향으로 각각 24 units 연장하고 끝을 잇는다. 원래 곡선은 유지하고 바깥 루프도 nonzero fill로 채운다. 직선·매끄러운 접선의 노드와 열린 끝점은 거부한다. 두 노드 드래그는 같은 닫힌 컨투어의 비인접 노드를 연결해 각 조각의 시작·끝 선분을 접선 방향으로 24 units씩 연장한 뒤 닫는다. 직선은 끝점을 옮기고 곡선은 기존 제어점을 보존한 채 접선 연장을 추가한다. 새 닫힘 선 위의 불필요한 직선 노드는 제거한다. 연결선은 내부에 있어야 하며 다른 컨투어와 만나는 겹침 영역은 거부한다. 관련 없는 컨투어는 재연산하지 않는다. 4-node X-overlap·Ink Trap은 구현 범위에서 제외한다. Harmonize는 후순위로 둔다.

자유변형은 편집 메뉴에서 선택한다. 경계의 8개 조절점은 크기, 위쪽 원형 조절점은 회전이다. Shift는 비율을 유지한다. 전체 컨투어를 뒤집을 때 winding을 보존하며 완료 좌표는 정수로 반올림한다. Esc 또는 다른 도구 선택으로 종료한다.

### Opt 클릭과 펜 호버 (2026-10-29)

선택 도구에서 Opt/Alt를 누른 채 직선 세그먼트를 클릭하면 양 끝점 사이 1/3·2/3 위치에 cubic 핸들을 만든다. 기존 곡선은 재설정하지 않으며 드래그와 클릭을 구분한다. 새 핸들도 정수 좌표 규칙을 따른다.

펜 도구의 세그먼트 인식 반경은 확대율과 관계없이 16 CSS px이다. 노드 삭제 판정을 우선한다. 클릭 중 8px 미만의 흔들림은 허용하며, 삽입 위치는 pointerdown 지점에서 윤곽선의 최근접점으로 투영한다. 호버의 +/− 힌트와 클릭은 같은 판정을 사용한다. 경로를 새로 그리고 있는 중에는 기존 윤곽 편집 힌트를 표시하지 않는다.

마우스·펜의 pointerenter/move를 받으면 도구 커서를 표시한다. hover 이벤트만으로 문서를 수정하지 않으며 pointerleave/cancel, 창 비활성화 때 커서를 지운다. 브러시·지우개는 단면 커서를 유지하고 나머지는 위치 십자선을 표시한다. 실제 기기의 hover 이벤트 수신은 별도 확인 대상이다.

## 극점과 사이드패널 (2026-11-01)

- 컨투어 → 극점 추가: 선택 노드·핸들·세그먼트가 속한 컨투어에 적용한다. 선택이 없으면 현재 레이어 전체에 적용한다. cubic의 x/y 도함수 내부 근에서 분할하며 기존 노드 ID·시작점·열림 여부를 유지한다. 기존 끝점에서 1 unit 이내는 정수 반올림 중복을 피하도록 생략한다. 확정 시 정수 반올림하며 한 번에 Undo한다.
- 리본 오른쪽 사이드패널 아이콘은 보기 → 사이드 패널과 같은 상태를 사용한다.
- 보기 → 사이드패널 왼쪽 배치는 조작부와 글리프 목록의 좌우를 바꾸며 브라우저 설정으로 기억한다. 휴대폰에서는 기존 하단 키 배치를 유지한다. Tab 전체 UI 숨김은 포함하지 않는다.

- 사이드패널과 글리프 목록은 편집 공간 쪽 경계 드래그로 폭을 조절하고 각각 기억한다. 최소 폭은 208px/96px, 최대 폭은 화면의 40%/25%로 편집 공간을 남긴다. 휴대폰에서는 폭 조절 대신 기존 하단 키 배치를 유지한다.
